# 2단계 검증 게이트 — 설계 방법론

이 킷과 자매 킷([policy-research-kit](https://github.com/parkjui92/policy-research-kit)·[socsci-paper-kit](https://github.com/parkjui92/socsci-paper-kit))이 공유하는 핵심 구조. "AI 초안을 어떻게 믿을 수 있게 만드는가"에 대한 우리의 답이다.

## 문제: 생성은 쉽고 신뢰는 어렵다

LLM 초안의 실패는 두 지점에서 온다.

1. **방향 실패** — 목차·연구질문이 요구를 빗나간 채 수십 페이지가 생성된다. 발견 시점이 늦을수록 폐기 비용이 커진다.
2. **근거 실패** — 그럴듯한 문장 속에 존재하지 않는 출처, 출처와 다른 수치, 유령 인용이 섞인다. 읽어서는 못 잡는다 — 대조해야 잡힌다.

두 실패는 성격이 달라서 **하나의 검수로는 못 막는다**. 그래서 게이트가 두 번이다.

## 게이트 1 — 집필 전 설계검토 (방향 실패 차단)

- **시점**: 설계자(designer/rfp-analyst)가 목차·RQ·평가대응표를 낸 직후, 조사·집필 착수 전.
- **검수자**: reviewer 에이전트 모드1. READ-ONLY — 자기가 고치지 않고 판정만 한다.
- **판정**: GO / 조건부 / NO-GO. 점검 항목 예 —
  - 요구(RFP·연구목적) ↔ 목차 1:1 매핑에 구멍이 없는가
  - 고배점 평가항목이 충분한 분량·깊이로 커버되는가 (제안서)
  - RQ가 답할 수 있는 질문인가, 분석틀이 실행 가능한가 (연구)
  - 분량 산술이 맞는가 (장별 합계 ≠ 목표 분량 같은 모순)
- **개정 루프**: 반려·조건부면 설계자가 개정 → 재검토, **최대 2회**. 그 뒤에도 남는 득점형 항목은 "잔여 리스크"로 기록하고 진행한다(무한 차단 방지). 남은 자격형(필수 요구가 목차에 없음 등)은 바로 뒤 사용자 승인 자리에 안건으로 올린다.
- **★사용자 승인**: 내부 게이트 통과 후 목차·핵심 RQ를 사용자에게 제시하고 승인받는다. 내부 게이트는 "실행 가능성"을, 이 게이트는 "의도 부합"을 본다.

## 게이트 2 — 집필 후 초안검수 (근거 실패 차단)

- **시점**: 초안 완성 직후, 변환(hwpx/docx) 전.
- **검수자**: reviewer 모드2. 위치·문제·해결을 갖춘 수정 요청을 [필수·자격]/[필수·득점]/[권고]로 낸다.
- **검수 축** (이 킷은 6영역): 요구사항 교차검증 / 평가지표 대응 / 논리·정량성 / **출처 대조** / 교열 / 계획형·서식 준수.
- **차단 기준 선기록**: 초안을 열기 전에 "무엇이 있으면 제출 불가인가"를 먼저 적는다. 잘 쓴 초안을 읽고 나면 기준이 초안 쪽으로 끌려간다.
- **출처 대조의 규율**:
  - 조사 파일과 초안을 맞춰 보는 것으로는 부족하다 — 조사 단계에서 잘못 옮긴 수치는 두 파일이 서로 일치한다. **검수자가 출처 원문을 직접 연다.**
  - 고배점 항목·필수 요구 근거·직접인용·법령 인용은 전수, 나머지는 표본
  - 문장의 수치가 N개면 대조 항목도 N개. 원문에 그대로 있는 수치와 계산·추정한 수치를 가른다
  - 판정은 ✅ 일치 / ⚠️ 부분 / ❌ 불일치 / 〔미개봉〕. "검색에 안 잡힌다"는 ❌가 아니라 〔미개봉〕이다
  - 조사관·작성가의 자기보고(〔검증완료〕 태그, 자기점검 노트)를 대조의 대체물로 쓰지 않는다. 열어 본 범위와 열지 못한 범위를 수로 적는다
- **개정 루프와 등급**: writer 반영 → 재검수, 최대 2회. 그 뒤의 처리는 등급에 따라 갈린다.

| 등급 | 뜻 | 2회 미해결 시 |
|---|---|---|
| [필수·자격] | 이대로 제출하면 안 되는 결함 — 필수 요구 미충족, 양식·분량·자격 위반, 원문과 다른 내용의 확정 기재 | 면제 없음. 판정 "보류" → 사용자가 보강·삭제·위험 수용 중 결정하고 그 결정을 기록 |
| [필수·득점] | 제출은 되지만 점수를 잃는 결함 | 잔여 리스크로 기록하고 진행 |

- **[필수] 철회 기준**: 작성가의 반론이 공고 원문·출처의 구체 위치를 짚고, 검수자가 그 위치를 직접 열어 확인했을 때만 철회한다. 말로 설득된 것은 철회 사유가 아니다.

## 설계 원칙 요약

1. **검증자는 생성하지 않는다** — reviewer는 READ-ONLY. 고치는 사람과 판정하는 사람을 분리한다. 선언에 그치지 않도록 에이전트 정의에서 편집 도구를 막아 둔다(`disallowedTools: Edit`).
2. **게이트는 문서로 남는다** — 판정·수정요청이 파일(`02_design_gate.md`, `05_review.md`)로 남아 사후 감사가 가능하다.
3. **득점형은 기록, 자격형은 사람에게** — 2회 루프 후에도 남은 득점형 결함은 진행하되 잔여 리스크로 투명하게 남긴다. 완벽주의로 파이프라인을 세우지 않는다. 다만 제출 자격을 깨는 결함은 루프 한도로 면제하지 않고 사용자에게 올린다 — AI가 사람 대신 위험을 수용하지 않는다.
4. **모르면 모른다고 쓴다** — 조사 단계부터 "근거 미확보 항목"을 명시하고, 집필은 `[보강 필요]` 태그로 이어받는다. 지어내지 않는 것이 규칙이 아니라 구조가 되게 한다.
