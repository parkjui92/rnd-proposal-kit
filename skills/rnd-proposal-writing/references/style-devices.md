## 2. 개조식 문체
- **종결형은 산출물 유형별 분기 — 착수 시 확인**: ① 단독 작업 초안 = "~함/~임" 개조식 ② 팀 통합본 = 마침표 없는 명사형 종결("…를 설계", "…을 산정") + 모듈 정의·의도 선언만 "~하고자 함" ③ 발주처가 서술식을 요구하는 산출물(위탁 최종보고서 등) = 서술식. 어느 단계에서도 "~한다/~합니다/~할 것이다/~된다" 금지체는 쓰지 않는다(전수 검사).
- **두괄식 블록**: 모든 □ 블록은 결론 요지 헤드라인 구절로 열고 긴 대시(—)로 부연을 잇는다. 세부 근거는 하위 글머리로 내린다.
- **1행 1문장 압축**: ◯ 수준 문장은 '근거→방법→산출'을 한 문장(60~120자)에 담고, － 수준은 그 실행 세부를 1문장씩 4~6개로 푼다.
- **한·영 병기**: 국제 전문용어는 첫 등장에 '한글 번역어(영문 원어)' 병기, 이후 한글어만. 예: 경유형(pass-through), 혼합금융(Blended Finance).
- **N대 넘버링**: 모든 개념 묶음에 개수 라벨(N대·N개·N축·N단계)을 붙여 반복 참조 가능한 고유명사로 만들고, 같은 묶음의 개수를 문서 전체에서 일치시킨다. 단, 타 파트와 대조되지 않은 명단·개수는 'N개' 확정 대신 "…등" 하한 표기로 모순 리스크를 차단한다.
- **한줄요약·헤드라인은 숫자 훅**: 눈길을 끄는 요약은 본문이 증명하는 구체 숫자로 쓴다(예: "직원 0명, AI 팀원 18명"). 본문↔요약 상호 증명 구조.

## 3. 방어 태그 체계 (미확정 정보의 성격별 고정 태그)
| 태그 | 용도 | 병기할 것 |
|------|------|-----------|
| 〔추정 — 확정치 사용 금지〕 | 수치 추정 | 추정 근거 |
| 〔보강 필요: 사유〕 | 자료·자문 대기 | 무엇이 오면 채워지는지 |
| 〔각주 필수〕 | 원표 대조 후 각주 처리 필요 | 대조할 원자료 |
| 〔가정 — 확정치 아님〕 | 정책결정 영역의 가정치 | 갱신 시점(예: 예산편성 시) |
| 〔사용자 확인〕 | 팀 사실·명단 대조 필요 | 대조 대상 |
| 〔합산금지〕 | 회계계정 상이 | 계정 구분 |
| 〔★차별화 핵심〕 | 득점 앵커 강조 (강조 태그는 이 1종만) | — |

태그에는 확정 경로(누가·무엇으로 확정)를 함께 쓴다. '계량화' 요구가 있는 RFP에서 규모 미확정 표를 그대로 두지 말고, 이미 인용된 벤치마크에 정박한 보수적 가정치 1줄을 〔가정〕 태그와 함께 추가한다.

## 4. 표 카탈로그
- **단계 프로세스 표**: `단계 | 시기 | 핵심 방법 | 주요 활용자료(출처) | 중간 산출물` 5열.
- **3원 매핑표**: `RFP 지정 산출물 | 설계 과업 | 결과예시` — 결과예시 절 서두.
- **모듈 인터페이스표**: `연계 모듈 | 본 모듈이 받는 입력 | 본 모듈이 주는 출력` (내부 추적용 — 팀 제출본에서는 제거).
- **미확정 예산표**: 확정 금액이 없으면 금액 대신 **● 상대강도 + 비중%**로 구조만 제시하고, ● 의미 범례와 '(가정)' 라벨, 확정 연동 경로를 표 주변에 명시.
- **표 명명**: 데이터형 산출물은 '○○표/매트릭스/DB/프로파일/정의서', 문서형 산출물은 「공식 문서명」(안). 표 실물을 그리기 전에 포함 항목(열 구성)을 － 불릿으로 먼저 명세한다.
- **2열 대응 표의 산문화**: "• 항목 — 얻는 것 ↔ 반대급부" 화살표 병기 불릿으로 정보 손실 없이 압축.

## 5. 〔삽도 프롬프트〕 규격
- **'삽도' = 개념도·구조도·논증 도해(도식)**이다. 사진풍 일러스트가 아니다. 축·노드·흐름이 명시된 도식 사양으로 제안한다.
- **이원 원칙**: 표는 본문에 직접 작성하고, 삽도는 생성용 프롬프트로 제안한다.
- **형식**: `※ 〔삽도 프롬프트 — 그림 N. 제목〕 "…"` 프롬프트 구성 순서: ① 위치어 기반 레이아웃(상단/중앙/좌측) ② 박스·화살표 구성요소와 연결관계 ③ 한글 라벨 원문 ④ 고정 스타일 클로저 — "파란 계열 플랫 디자인, 흰 배경, 한글 라벨, 정부/관공서 보고서 스타일".
- **프롬프트는 한국어**로 쓴다(HEX·비율 등 기계 파싱값만 원문 유지). 덱 등 다장 작업은 공통 스타일 잠금(STYLE LOCK) 문구를 만들어 전 프롬프트 끝에 동일하게 붙인다.
- **세트 제안**: 시각자료는 1~2개가 아니라 6~10종 세트(우선순위 포함)로 제안한다.
- **산출 단계별 3단 강도**: 작업본 = 생성용 상세 프롬프트 / 변환본 = 1줄 요약 + "(최종본 삽입 예정)" / 팀 제출본 = 〔그림(안): 한 줄 설명〕. 상세 프롬프트는 상위 버전 파일에 보존해 디자이너 입력용으로 남긴다.

## 6. 수치·출처 규율
- 수치가 있는 문장에는 예외 없이 출처·연도를 밀착 병기한다. 근거는 협정문·사업문서(prodoc)·연차보고서 등 **1차자료 우선**, 해외 자료는 현지어 검색 병행.
- 조사 산출물에는 **클릭 가능한 원문 URL**을 달고 〔검증완료〕/〔미검증〕을 항목별 표기한다 — 사용자가 원문을 직접 대조한다는 전제로 작성.
- 출처가 다른 재정 수치는 회계계정 동일성 확인 전 **절대 합산하지 않는다**. 이 원칙 자체를 품질관리 원칙으로 본문에 명문화한다.
- 예산·사업비 표는 공고의 집행항목·자부담 인정 규정과 대조해 편성한다(자부담은 어차피 지출되는 항목으로 채우는 실익 설계 포함).
