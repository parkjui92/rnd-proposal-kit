# 계획형 집필 골격 (실전 R&D 공동 제안서 모듈 5종으로 검증, 2026-07)

제안서·계획서 유형(위탁·수립지원·세부수행 모듈)의 기본 골격. **근본 규칙: 제안서는 아직 안 한 일의 계획서다 — 완성된 설계 결과처럼 쓰지 말라.** 설계 결과형(주제별 가나다 절에 완성 내용 서술)은 "이미 다 한 것처럼" 읽혀 방법론 배점을 놓친다.

## 3단 골격

최상위 목차는 내용 주제가 아니라 **'방향–방법–산출'의 단계**다. 1./2./3. 아라비아 3부로 구성한다.

### 1. 추진방향
- **첫 블록 = 과업 목표 두괄식**: "□ 과업 목표 — '(산출물 성격 한 구절)' 산출" 헤드라인으로 열고, RFP가 요구하는 항목 **전체를 괄호 안에 슬래시로 나열**해 "빠짐없이 정조준함"을 첫 화면에서 입증한다.
- **3대 설계 원칙 (차별화 포인트)**: 차별성은 '결과의 자랑'이 아니라 '설계 원칙'으로 프레이밍한다. 원칙 중 최소 1개는 RFP 지시문을 따옴표로 직접 인용하고 "…요구를 정조준함"으로 대응을 선언한다.
- **설계의 준거 — 반면교사·성공사례 쌍**: 방향 정당화는 실패사례(반면교사) 1건 + 성공사례 1건의 쌍으로 제시하고 각각 수치·연도·출처를 붙인다.

### 2. 수행방법론 및 추진과정 — 4요소 필수
1. **단계 프로세스 표** (5열): `단계(원문자+명칭) | 시기(착수~N개월) | 핵심 방법 | 주요 활용자료(출처) | 중간 산출물` — 단계마다 중간 산출물명을 반드시 특정한다.
2. **N축 분석틀**: 검토 차원을 명명한 분석틀(예: "5축 분석틀: 법적 형태/거버넌스/재원구조/분담·단가/성과관리").
3. **전문가 자문 계획**: 자문 영역 구분 + "자문 의견의 설계 반영 이력을 관리"까지 명시.
4. **품질관리 원칙**: 모든 수치에 공식 1차자료 출처 병기 / 미확정치는 방어 태그로 구분(→ style-devices.md) / 서로 다른 회계계정의 수치 합산 금지.
- 본문의 설계 내용은 **"(설계N) ~을 …방법으로 설계/도출함 → 결과예시 N"** 형태의 수행 과업 서술로 쓴다. 모든 설계 과업이 결과예시를 정확히 하나 이상 지목하는 전방참조 체인을 만든다.

### 3. 결과예시 — 산출물 미리보기
- **서두에 3원 매핑표**: `RFP 지정 산출물 | 설계 과업(2절) | 결과예시` — 재구성 후에도 요구 커버리지가 추적 가능함을 보인다.
- **미리보기 면책문(필수)**: 서두에 "이하 예시는 최종 산출물의 형태·수준을 보여주는 미리보기이며, 세부 수치·구성은 과업 수행(○○·○○)을 통해 확정함" — 확정 경로(무엇으로 확정되는지)를 괄호로 특정한다.
- **표 라벨**: 기존·완성형 콘텐츠의 표는 버리지 말고 "□ 예시 N 〈표 제목〉 — 설계N의 산출 형태(입력 프레임)"로 재라벨해 이 절에 배치한다. 표 제목은 〈 〉로 감싼다.
- 도식 자리는 〔삽도 프롬프트〕로 채운다(규격은 style-devices.md).

### 말미: 기대효과 블록
"□ 기대효과 — 본 과업 수행으로 발주기관은 ①…②…③…을 확보하여, **(시점·용도)에 즉시 활용**할 수 있음" — 발주기관 관점의 확보물 3개 + 즉시 활용처로 닫는다.

## 논증 패턴 3종
- **검증된 구조의 이식 + 발주국 선례**: 새 제도 제안은 "발명이 아니라 이미 운용 중인 국제 표준구조의 도메인 이식"으로 프레이밍하고, 한국(발주국)의 실제 참여 선례를 수치와 함께 붙여 실행가능성을 입증한다.
- **선례 부재의 정직 인정 → 상위 표준 정당화**: 선례 없는 제안은 부재를 숨기지 말고 명시적으로 인정한 뒤, 상위 표준·규범(회계기준·국제원칙)을 근거로 "선도적 방식"으로 명명한다.
- **피상 부정 → 실행 긍정 대비 구문**: 블록마다 "단순 ○○에 그치지 않고/머무르지 않고 …" 형태로 피상적 접근을 부정하고 실행·검증 지향을 긍정해 차별성을 논증한다.

## 재구성·개정 시 규율
- **사실 동결**: 검수를 통과한 사실·수치·출처는 문자 그대로 이관하고 새 수치를 만들지 않는다. 신설은 방법론·일정·절차 서술로 한정한다.
- **버전 보존**: 전면 재구성 시 구버전을 `_prev/`에 보존하고, 새 파일 인용구 헤더에 버전명·재구성 사유·지시 날짜·구버전 위치를 기록한다.
- **검수 통과 기준의 선반영**: RFP 요구 전 항목의 섹션 매핑 확보 / 모든 수치의 조사파일(02) 1:1 대조 가능 / 차별화 앵커의 추진방향 전진배치 / 계정 합산금지.
