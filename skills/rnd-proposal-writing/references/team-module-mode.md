# 팀 공동 제안서 — 모듈 모드 (실전 팀 통합본으로 검증, 2026-07-18)

사용자가 팀 제안서의 **담당 모듈만** 집필·개정하는 모드. 목표는 "다른 사람들이 작성한 것과 어울려 하나의 제안서가 되는 것"이다. 팀원 원고를 문체 표본으로 정독한 뒤 시작하고, 원본 한글 파일 서식을 깨뜨리지 않는다.

## 집필 범위
- 사용자 담당 모듈만 쓴다. 사용자의 기획 메모(개조식 ~함 문장들)는 **약속된 커버리지 체크리스트**다 — 메모의 전 요소를 본문에 구현한다.
- 타 모듈 내용은 쓰지 않되, 연계는 명시한다(아래 골격 5).

## 팀 모듈 골격 (동료 완성 모듈 5종에서 추출)
1. **첫 □ = 통합 프레임 선언**: 세부과업 나열 전에 모듈 전체를 '하나의 통합 설계/분석 체계'로 정의하고, 분석틀·자료원·검증절차(전문가 자문·발주기관 협의)·타 모듈 연계를 선언한다. "개별 조사를 병렬 수행하지 않고 일관된 분석틀 안에서 수행" 류의 통합 선언 포함.
2. **중간 □들 = RFP 소항목 순서 보존 + 조사→설계→검증 흐름**으로 배열.
3. **□ 제목 = RFP 소항목 명사구 보존 + 결과 지향 술어**: "RFP 요구 키워드 + 설계(안) 도출/수립/마련". 분량 초과 시 RFP 인접 요구끼리 블록 병합.
4. **작년 연구성과(선행연구) 활용 블록**: "그대로 반복하지 않고 올해 기준(RFP·수요)으로 재검증·재구조화한다"는 논리로 전용 □ 또는 마지막 □ 내 ◯로 넣는다.
5. **교차참조**: 받는 입력("1-N에서 도출한 …를 근거로")과 주는 출력("…를 모듈 N의 …에 직접 연계")을 각각 최소 1회 문장으로 명시. 표준 동사는 '정합', '일원화', '중복 편성 방지'. 소관 경계(예: 상위 거버넌스는 1-4 소관)를 명시해 중복 차단.
6. **마지막 □ = "핵심 산출물 작성(도출) 및 후속 세부과업 연계"** (팀 표준 제목): 산출물별 ◯ + 구성요소 － + 연계 모듈 명시.

## 서식 규격 (자기점검 수치까지)
- **평면 □ 블록 구조**: 마크다운 헤딩(##)·번호 대분류(1./2./3.) 금지. □ 블록 8~9개 나열로 3단 계획 논리(방향→방법→산출)를 블록 순서로 유지.
- **글머리 4단 유니코드**: □(U+25A1) → ◯(U+25EF) → －(U+FF0D) → •(U+2022, 최소화). 유사 문자(○ U+25CB, 반각 하이픈)를 유니코드 검사로 0건 확인. 본문 위계는 3단(□–◯–－)이 기본, 4수준 남발 금지.
- **• 목록의 본문 변환**: 메모의 • 목록은 (i) 한 문장 내 ①②③ 인라인 열거 또는 (ii) － 하위 불릿으로 변환하고 본문에 •를 남기지 않는다.
- **문체**: 계획형 개조식 — 상위 "~하고자 함", 하위 명사형 종결("…설계/…도출/…설정"). 금지체(~한다/~합니다/~할 것이다/~된다) 0건 전수 검사.
- **제거 목록**: 마크다운 볼드 0건(강조는 블록 제목과 문두 배치로) / 타 모듈 담당자명(순수 '1-N' 표기만) / 내부 넘버링('설계N'·'결과예시 N' 상호참조 — 단독 초안까지만 쓰는 내부 장치) / 내부 추적용 표(3원 매핑표·인터페이스표).
- **표 압축**: (1) RFP가 표 형태를 명시 요구한 것 (2) 차별화 핵심 구조 (3) 핵심 계량표만 남기고(6종 내외) 나머지는 개조식 산문 전환.
- **통화 표기**: 산문은 한글 단위(달러·유로·스위스프랑), 표 안은 US$ 유지.
- **분량**: 팀 문서의 동급 모듈 실측 범위에 맞춘다(실측 사례: 공백 포함 12,000~18,000자).

## 출처·마커의 단계별 격리
- **출처**: 초안 인라인 〔출처〕 → 팀 제출본에서는 기관명·문서명·연도를 문장 안에 서술로 녹인다. 출처 원목록은 삭제하지 말고 작업 노트로 이관해 각주 처리용으로 보존.
- **작업 마커 3단계**: 작업 초안 = 인라인 태그 + 말미 메모 / 변환본 = 인라인 태그만 / 팀 제출본 = 본문 무마커(표 안 '(가정)' 라벨만 허용) + 별도 노트에 `항목|상태|본문 처리 방식|확정 조치` 표로 전수 보존.
- **하드 카운트 회피**: 타 모듈과 대조되지 않은 명단·개수는 "…등" 하한 표기.

## RFP 급소 이식
- RFP의 **※·단서 요구는 평가 급소** — 해당 모듈 본문에 같은 어휘(직접 근거, 착수 전제조건, 연계)로 1회 이상 재진술한다.
- RFP 산출물표의 산출물명을 모듈 산출물 명명에 그대로 쓴다(「」+(안)).

## 통합 노트 의무
팀 통합·서식 전환 시 반드시 동반 노트(`04c_notes.md` 류)를 작성한다:
① 구조 변경 요약(기호·문체 포함) ② 마커 이관표 ③ 출처 이관 ④ 삭제·축약 목록 ⑤ 자기점검(기호 유니코드 카운트, 금지체 0건, RFP 요구 커버 N/N, 분량) ⑥ 사용자 확인 필요 항목.

## 개정 요청 처리
- 발주처 의견·회의록이 입력되면 항목별 반영/무시 여부를 표로 확인받고, 지정 부분만 정밀 수정한다. 사용자가 공들인 원본 문구·양식은 백업 후 보존.
- 항목 삭제 지시는 완전 삭제가 아니라 문서 하단 "▽ 검토 후 제외" 블록으로 이동·보존.
- 사용자가 "내가 직접 수정할게"라고 하면 파일 편집을 중단하고, 바로 붙여넣을 수 있는 개조식 문장 후보(논거 메뉴)를 채팅으로 제공한다.
