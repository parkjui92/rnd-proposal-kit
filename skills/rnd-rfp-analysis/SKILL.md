# R&D 공고/RFP 분석

정부 R&D 과제 공고를 분석해 제안서의 골격(목차)과 득점 전략(평가대응표)을 만든다. 이 분석이 제안서 전체의 방향을 결정하므로 정밀해야 한다.

## 왜 이 단계가 중요한가
평가위원은 정해진 평가표로 채점한다. 공고가 요구한 것을 빠뜨리면 자격 미달이고, 배점을 모르면 엉뚱한 곳에 지면을 쓴다. 이 스킬의 산출물이 작성가의 지도가 된다.

## 절차

### 1. 원문 확보
- `_workspace/00_input/`의 공고 파일을 추출한다: .hwpx/.pdf/.docx는 `mcp__kordoc__parse_document`, .md/.txt는 Read, URL은 `WebFetch`.
- 공고문·과제제안요구서(RFP)·신청요령이 여러 파일이면 모두 읽고 통합한다.

### 2. 5대 추출
다음 다섯 가지를 빠짐없이 뽑는다:

**(A) 필수 요구사항** — 개발 목표, 정량/정성 성과지표(TRL, 특허, 논문, 매출 등), 의무사항. 필수("하여야 한다")와 권장("할 수 있다")을 구분 표기한다.

**(B) 평가지표·배점** — 평가표가 있으면 항목·배점·세부기준을 표로 옮긴다. 배점은 곧 지면 배분의 근거다.

**(C) 양식·분량·자격 제약** — 지정 서식 유무, 페이지 한도, 글꼴·여백, 신청 자격, 매칭펀드 비율, 연구기간, 제출 서류 목록.

**(D) 핵심 키워드** — 공고가 반복하는 용어. 제안서 본문에 그대로 사용해 일치도를 높인다.

**(E) ※·단서 급소** — RFP 본문의 ※ 표시·괄호 단서·"~되어야 하며"류 조건문("직접 근거가 되어야", "착수 전제 조건으로 설계" 등). 누락 위험이 가장 큰 평가 급소이므로 별도 목록화하고, 작성가가 본문에 같은 어휘로 재진술하도록 대응 섹션을 지정한다.

### 3. 과제 유형 분류 + 제안서 목차 설계
먼저 과제 유형을 분류한다 — 목차 기준이 달라진다:
- **기술개발형** (TRL·성능지표·사업화 요구) → R&D 표준 구조(필요성 / 목표·내용 / 추진전략·체계·일정 / 기대효과·활용방안 / 수행역량 / 예산)
- **위탁·정책수립형** (수립지원·위탁연구·용역) → 계획형 3단(추진방향 / 수행방법론·추진과정 / 결과예시) 기반. 과업 이해도·수행방법이 배점 중심
- **지원사업 신청형** (지정 신청서식 존재) → 서식 항목이 곧 목차. 서식을 파싱해 항목 순서 그대로 설계
- **팀 공동 제안서의 담당 모듈** → RFP 해당 항목(소항목 포함)만 범위로, 팀 서식 정합 전제

발주처가 지정 목차를 줬으면 그대로 따른다. 없으면 위 유형 기준 구조에, 평가배점이 높은 항목에 더 많은 하위 항목을 배정한다. 목차·블록 제목에는 RFP 소항목의 명사구를 보존한다(평가위원 추적 가능성).

### 4. 평가대응표 작성
평가항목마다 "제안서의 어느 섹션이 이 항목에 득점하는가"를 매핑한다. 빈칸(대응 섹션 없는 평가항목)이 있으면 목차를 보완한다.

## 출력 구조

`_workspace/01_rfp_analysis.md`에 다음 구조로 저장한다:

```markdown
# RFP 분석: <과제명>

## 0. 과제 개요
- 사업명 / 공고기관 / 과제유형 / 연구기간 / 총 사업비 / 매칭펀드 / 신청마감
- 골격 유형 판정: 기술개발형 | 위탁·정책수립형 | 지원사업 신청형 | 팀 모듈형 (판정 근거 1줄)

## 1. 필수 요구사항
| # | 요구사항 | 필수/권장 | 공고 근거 |
|---|----------|-----------|-----------|

## 1b. ※·단서 급소
| # | 단서 원문 | 요구 어휘 | 재진술할 섹션 |
|---|-----------|-----------|---------------|

## 2. 평가지표 및 배점
| 평가항목 | 배점 | 세부 기준 |
|----------|------|-----------|
(배점 합계와 가중 우선순위 명기)

## 3. 양식·분량·자격 제약
- 지정 양식: (있음/없음 — 있으면 파일명) / 페이지 한도 / 글꼴·여백 / 자격 / 제출서류

## 4. 핵심 키워드
(공고 반복 용어 목록)

## 5. 제안서 목차 (권장)
(섹션 구조 + 각 섹션 예상 비중 %)

## 6. 평가대응표
| 평가항목 | 배점 | 대응 제안서 섹션 | 조사 필요 근거 |
|----------|------|------------------|----------------|

## 7. 사용자 확인 필요 사항
(공고 미명시·모호 항목)
```

## 주의
- 공고에 없는 제약을 지어내지 않는다. 미명시는 7번 섹션에 모은다.
- "조사 필요 근거" 열은 리서치 조사관에게 전달되는 작업 지시가 된다 — 구체적으로 적는다.
- 발주처 용어를 변형하지 않는다.
