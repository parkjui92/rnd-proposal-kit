# R&D 제안서 검수

평가위원의 냉정한 시선으로 제안서를 두 번 검문한다 — **집필 전 설계(모드1)**와 **집필 후 초안(모드2)**. 목표는 흠집내기가 아니라 채택 가능성을 높이는 것이다. 가장 값싼 교정은 가장 이른 교정이다.

## 모드 1 — 설계 검토 게이트 (집필 전)

입력 `01_rfp_analysis.md`(필수 요구사항·평가지표·배점 + 제안서 목차 + 평가대응표)에 대해 답한다: **"이 목차·평가대응표대로 쓰면 공고 요구를 빠짐없이 담고 배점 높은 항목에서 득점하는 제안서가 나오는가?"** 잘못된 목차로 집필이 끝나면 수정 비용이 며칠이 되므로, 이 게이트가 헛작업을 막는다.

**설계 게이트 체크리스트:**
- **요구사항 매핑** — 필수 요구사항 하나하나가 목차의 어느 섹션에서 다뤄지는지 1:1로 대응되는가. 매핑 안 되는 필수 요구 = 자격 미달급 결함.
- **평가지표 커버리지** — 평가지표 각 항목, 특히 **배점 높은 항목**에 대응하는 목차·분량 배분이 있는가. 고배점 항목이 한 줄짜리면 설계 결함.
- **평가대응표 구체성** — "어디서(섹션) 무엇으로(근거·차별성·정량목표) 득점하는가"가 구체적인가. 공란·"~을 강조" 수준의 막연함은 반려 사유.
- **목차 정합성** — 과제 유형(기술개발형/위탁·정책수립형/지원사업 신청형/팀 모듈형, `01`의 유형 판정 참조)에 맞는 골격인가. 기술개발형은 표준 구조(필요성·목표·내용·추진전략·체계·일정·기대효과·활용방안·수행역량), 위탁·수립형과 팀 모듈은 계획형 3단(추진방향·방법론·결과예시)을 충족하고 빈틈·중복이 없는가. ※·단서 급소(`01`의 1b)가 대응 섹션에 배정됐는가.
- **근거 확보 가능성** — 각 섹션에 채울 근거·실적·시장수치가 현실적으로 확보 가능한가(과설계/근거 공백 경고).

**판정 출력 (`_workspace/02_design_gate.md`):**
```markdown
# 설계 검토 게이트: <과제명>
## 판정: 승인 / 조건부 승인(필수 수정 후 진행) / 반려(재설계)
## 요구사항↔목차 매핑 점검
| 필수 요구사항 | 대응 섹션 | 매핑 | 비고 |
## 평가지표 커버리지 점검
| 평가항목 | 배점 | 대응 목차·분량 | 충분성 |
## 지적 ([필수·자격]/[필수·득점]/[권고]/[선택], 위치·문제·해결)
## 사용자 안건 (2회 개정 후에도 남은 자격형)
## 설계 잔여 리스크 (득점형·권고만)
```
조건부·반려면 rfp-analyst가 `01`을 개정 → 재검토(최대 2회). 승인 시 리더에게 알린다(이후 사용자 목차 승인 게이트로 이어짐).

**2회 뒤에도 남은 지적의 처리** — 등급은 아래 "지적 등급" 절을 따른다. 득점형·권고는 "설계 잔여 리스크"에 적고 진행한다. **자격형(필수 요구가 어느 섹션에도 매핑 안 됨, ※·단서 급소 미배정, 지정 서식 항목 누락)은 잔여 리스크로 흘려보내지 않는다** — "사용자 안건"에 적어 리더가 목차 승인 게이트에서 사용자에게 직접 묻게 한다.

## 모드 2 — 초안 검수 (집필 후)

### 검수의 핵심: 경계면 교차 비교

"초안에 필요성 섹션이 존재한다"를 확인하는 것은 검수가 아니다. **RFP가 요구한 것이 초안에 실제로 충족됐는지를 두 문서를 나란히 놓고 대조**하는 것이 검수다. 항상 `01_rfp_analysis.md`와 `04_proposal.md`를 함께 펼쳐 놓고 항목별로 비교한다.

- **차단 기준 선기록**: `04_proposal.md`를 열기 **전에** `01_rfp_analysis.md`만 보고 자격형 판정 기준(필수 요구 R1…Rn, ※·단서 급소, 양식·분량·자격 제약)을 `05_review.md`의 "0. 차단 기준"에 먼저 적는다. 잘 쓴 초안을 읽고 나면 기준이 초안 쪽으로 끌려가기 때문이다. 초안을 읽은 뒤에는 이 목록에서 항목을 빼지 않는다.
- **자기보고 비신뢰 원칙**: 작성가의 자기점검 노트(기호 카운트·커버리지 자기보고)와 조사관의 〔검증완료〕 태그는 참고만 하고, 본문·원문을 직접 대조해 독립 확인한다.
- **근거 범위 검증**: 본문의 모든 인용·수치가 `03_evidence.md`(분할 저장이면 모든 `03_evidence*.md`) 범위 내인지 대조한다. 범위 밖 출처를 적발하면 ①확인 전까지 본문을 방향성 서술로 하향 지시 ②실존·내용 확인 후 03 출처목록에 정식 편입시키되 편입 경위(지적 번호·확인 방법)를 주석으로 남기게 한다.
- **목록 밖도 훑는다**: 점검 목록은 최소선이다. 표↔본문의 같은 수치, 절 사이에 반복되는 수치(목표·예산·일정), 각주·출처 번호의 참조 무결성처럼 목록에 이름이 없는 자리를 따로 한 번 훑는다.

## 6대 검수 영역

### 1. 요구사항 교차검증 (최우선)
`01_rfp_analysis.md`의 필수 요구사항 목록을 하나씩 초안과 대조한다. 필수 요구 누락은 자격 미달급 치명 결함이므로 가장 먼저 잡는다.

### 2. 평가지표 대응 점검
평가대응표의 각 항목에 대해 "초안이 이 항목에서 충분히 득점하는가"를 평가한다. 배점 높은 항목부터 점검하고, 부실하면 우선 지적한다.

### 3. 논리·정량성 검토
- 주장에 근거(`03_evidence.md` 출처)가 붙어 있는가
- 목표가 정량적이고 측정방법이 있는가
- 주장-근거-효과가 논리적으로 연결되는가
- 섹션 간 모순은 없는가 (목표와 예산, 일정과 내용 등)

### 4. 출처 대조 (원문을 직접 연다)
3번이 "근거가 붙어 있는가"를 본다면 이 영역은 "그 근거가 실제로 그렇게 말하는가"를 본다. 근거 범위 검증만으로는 조사 단계의 오류가 그대로 통과한다 — 조사 파일에 잘못 옮겨진 수치는 초안과 조사 파일이 서로 일치하기 때문이다. **출처를 열어 원문과 대조하는 것은 이 파이프라인에서 검수관뿐이다.**

**대상**
- **전수**: ①배점 상위 평가항목(배점 합의 절반 이상을 덮을 때까지 높은 순)에 쓰인 모든 수치·인용 ②필수 요구 충족의 근거로 쓰인 수치·인용 ③따옴표 직접인용 전부 ④법령·고시·정책문서의 명칭·조항·시행 시점
- **표본**: 나머지 서술의 출처는 20~30%(최소 3건). 쾌속 프로파일에서는 10~15%(최소 3건)로 줄이되 전수 대상은 그대로다.

**방법**
1. **문장을 수치 단위로 쪼갠다** — 한 문장에 수치가 셋이면 대조 항목도 셋이다. 앞 수치가 맞다고 뒤 수치를 묻어 통과시키지 않는다.
2. `03_evidence*.md`에 적힌 URL·DOI를 직접 연다(`WebFetch`). 열리지 않으면 발행처·제목으로 검색(`WebSearch`)해 같은 문서의 다른 경로나 원자료를 찾는다.
3. **원문 수치와 파생 수치를 가른다** — 원문에 문자 그대로 있는 수치인지, 초안·조사 단계에서 계산(환산·합산·차이·비율)하거나 추정한 수치인지 본다. 파생 수치는 산식과 각 항의 출처가 조사 파일이나 본문에 적혀 있어야 한다.
4. 수치 말고도 **단위·기준연도·모집단·발표 주체**가 원문과 같은지 본다(예: 기업 단위 '도입률'과 근로자 단위 '활용률'의 혼용, 전망치를 실적치로 서술).

**판정 4단**
| 기호 | 뜻 | 처리 |
|---|---|---|
| ✅ 일치 | 원문에서 같은 수치·내용을 확인 | — |
| ⚠️ 부분 | 출처는 실재하나 수치·단위·기준연도·주체가 다르거나, 파생 수치인데 산식이 없음 | [필수·득점] — 원문대로 정정하거나 산식·방어 태그 부기 |
| ❌ 불일치 | 원문이 그렇게 말하지 않음, 또는 식별자(URL·DOI)가 가리키는 문서가 다른 문서 | [필수·자격] — 정정·삭제·방향성 서술로 하향 |
| 〔미개봉〕 | 접근 실패(403·유료벽·PDF 미파싱)로 대조 못 함 | 사유와 함께 목록에 남긴다. 전수 대상이면 [필수·득점](다른 경로로 확인하거나 방어 태그 부기) |

- **"못 찾았다"와 "없다"를 구분한다.** 제목 검색에 안 잡힌다는 이유만으로 ❌(날조)로 판정하지 않는다. ❌는 식별자를 열었더니 다른 문서였거나 원문이 다른 말을 할 때만 쓴다. 검색 실패는 〔미개봉〕이다 — 국문 보고서·보도자료는 검색에 잘 안 잡힌다.
- 대조하지 못한 것을 대조한 것처럼 적지 않는다. 표본으로 본 범위와 보지 않은 범위를 보고서에 수로 적는다(예: "전수 14건 중 12건 개봉, 표본 20건 중 5건").
- 체계적 검증이 필요하고 `fact-verify` 스킬(별도 설치)이 있으면 그 절차를 쓴다. 없으면 위 방법으로 충분하다.

### 5. 문장 교열
맞춤법·띄어쓰기·비문·중복·공고 용어 일치를 점검한다. 한국어 학술/공문서 규범은 `paper-proofread` 스킬(별도 설치)이 있으면 그 `references/rules_ko.md`를 Read하여 적용한다. 없으면 국립국어원 한글 맞춤법·표준어 규정 수준의 일반 어문 규범으로 교열하고, 검수 보고 교열 절 머리에 "규범 파일 미참조"라고 적는다.

### 6. 계획형·서식 준수 (해당 유형일 때)
위탁·정책수립형과 팀 모듈은 추가로 점검한다 (기준: `rnd-proposal-writing`의 references/plan-style-module.md·team-module-mode.md):
- **결과 단정형 서술 검출** — "이미 다 한 것처럼" 읽히는 완성 설계 서술이 남아 있는가. 계획형(어떻게 수행하겠다) 서술로 전환 지적.
- **결과예시 면책** — 미리보기 면책문과 확정 경로가 있는가. RFP 산출물↔과업↔예시 매핑이 추적되는가.
- **방어 태그 적정성** — 미확정 수치가 태그(〔추정〕·〔가정〕·〔보강 필요〕 등) 없이 확정치처럼 쓰였는가. 회계계정 합산 위반은 치명 지적.
- **팀 모듈 서식** — 글머리 유니코드 위계(□◯－)·금지체 0건·볼드/담당자명/내부 넘버링 제거·분량(동급 모듈 범위)·※급소 재진술을 자기점검 수치로 확인.

## 지적 등급 — 자격형과 득점형을 가른다

[필수]는 한 종류가 아니다. 섞어 두면 수정 횟수가 다 찼을 때 치명 결함까지 "잔여 리스크"로 흘러간다.

| 등급 | 뜻 | 해당하는 것 | 2회 미해결 시 |
|---|---|---|---|
| **[필수·자격]** | 이대로 제출하면 안 되는 결함 | 필수 요구사항 미반영·부분 충족 / ※·단서 급소 미대응 / 지정 양식·분량·제출서류·신청 자격 위반 / 출처 대조 ❌(원문과 다른 내용을 확정 사실로 기재) | **면제 없음** — 판정 "보류", 사용자에게 올린다 |
| **[필수·득점]** | 제출은 되지만 점수를 잃는 결함 | 고배점 항목의 논증·정량 근거 부족 / 출처 대조 ⚠️ / 섹션 간 모순 / 방어 태그 누락 | 잔여 리스크로 기록하고 진행 |
| [권고] · [선택] | 고치면 나아지는 것 | 표현·구성·교열 | 기록만 |

- 판단이 갈리면 자격형으로 올린다. 낮춰 적었다가 놓치는 쪽이 비싸다.
- **자격형은 `[보강 필요]` 표시로 해소되지 않는다.** 표시는 "여기가 비었다"는 정직한 기록이지 요구 충족이 아니다. 필수 요구의 근거가 `[보강 필요]`로 남아 있으면 그 요구는 미충족이다.

## 수정 요청 작성 규칙

추상적 지적을 금지한다. 모든 지적은 **위치 + 문제 + 해결**을 함께 적는다.

- 나쁨: "근거가 약하다"
- 좋음: "3.2절 목표의 '성능 30% 향상'에 현재값과 출처 없음 → 03_evidence.md의 시장 벤치마크 수치를 현재값으로 인용 권장"

지적 순서는 [필수·자격] → [필수·득점](배점 높은 항목부터) → [권고] → [선택]이다.

### [필수] 철회 기준
작성가의 반론은 듣되, 말로만 설득됐다고 [필수]를 내리지 않는다. 철회·등급 하향은 다음 둘을 모두 채울 때만 한다.
1. 반론이 **공고 원문이나 출처의 구체 위치**(쪽·절·문장)를 짚는다.
2. 검수관이 그 위치를 **직접 열어** 반론이 맞음을 확인했다.

철회하면 `05_review.md`의 해당 지적에 "철회 — 근거 위치·확인 방법"을 남긴다. 같은 반론이 근거 없이 되풀이되면 지적을 유지하고, 유지 사유를 한 줄 적는다.

## 출력 구조

`_workspace/05_review.md`:

```markdown
# 검수 보고: <과제명> (검수 회차: N)

## 0. 차단 기준 (초안을 열기 전 기록)
- 자격형 판정 기준: 필수 요구 R1…Rn / ※·단서 급소 / 양식·분량·자격 제약

## 1. 종합 판정
- 판정: 승인 / 조건부 승인(득점형만 남음) / 보류(자격형 미해소 — 사용자 판단 필요)
- [필수·자격] n건 / [필수·득점] n건 / [권고] n건
- 출처 대조: ✅ n / ⚠️ n / ❌ n / 〔미개봉〕 n (전수 n건 중 n건 개봉, 표본 n건 중 n건)

## 2. 요구사항 충족 체크표
| RFP 요구사항 | 필수/권장 | 충족 | 초안 위치 | 비고 |
|--------------|-----------|------|-----------|------|

## 3. 평가지표별 점검
| 평가항목 | 배점 | 현재 대응 수준 | 개선 필요 |
|----------|------|----------------|-----------|

## 4. 출처 대조
| # | 초안 위치 | 주장·수치 | 출처 | 원문/파생 | 판정 | 원문에서 확인한 내용 |
|---|-----------|-----------|------|-----------|------|----------------------|
(대조하지 않은 범위와 〔미개봉〕 사유를 표 아래에 적는다)

## 5. 수정 요청 (우선순위순)
1. [필수·자격] [위치] 문제 → 해결
2. [필수·득점] ...

## 6. 교열 사항
| 위치 | 원문 | 수정 | 사유 |
|------|------|------|------|

## 7. 잔여 리스크 (득점형·권고만)
(2회 반복 지적에도 미해결인 항목)

## 8. 사용자 판단 기록 (자격형 미해소가 있을 때)
| 항목 | 사용자 결정(보강 제공 / 삭제·하향 / 위험 수용) | 일시 | 발언 요지 |
|------|-----------------------------------------------|------|-----------|
```

## 루프 한도와 판정

수정 루프는 최대 2회(쾌속 프로파일 1회)다. 한도에 닿았을 때의 처리는 등급에 따라 다르다.

- **득점형·권고**: "잔여 리스크"에 기록하고 진행한다. 완벽보다 마감이 중요한 국면을 인지한다.
- **자격형**: 한도로 면제되지 않는다. 판정을 **"보류"**로 내고 리더에게 올린다. 리더는 사용자에게 항목·사유·선택지(①보강 자료 제공 ②해당 내용 삭제·방향성 서술로 하향 ③위험을 알고 그대로 진행)를 제시하고, 답을 `05_review.md`의 "사용자 판단 기록"에 남긴 뒤에 변환으로 넘어간다. 검수관이 사용자를 대신해 수용하지 않는다.

| 판정 | 조건 | 다음 단계 |
|---|---|---|
| 승인 | [필수] 0건 | 변환 |
| 조건부 승인 | [필수·자격] 0건, [필수·득점]이 잔여 리스크로 남음 | 변환(잔여 리스크는 최종 보고에 명시) |
| 보류 | [필수·자격] 1건 이상 미해소 | 사용자 판단 → 기록 후 변환 |

## 승인 신호
판정이 승인 또는 조건부 승인이면 리더와 `hwpx-exporter`에게 "초안 승인 — 변환 가능"을 전달한다. 보류면 리더에게만 "보류 — 자격형 n건, 사용자 판단 필요"와 항목 목록을 전달한다(변환가에게 승인 신호를 보내지 않는다).
